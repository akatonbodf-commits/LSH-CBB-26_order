# **2026 CBB \- イベント物販事前注文 & POSレジシステム**

イベント会場での物販における混雑緩和とオペレーション効率化を目的とした、**事前注文・キャッシュレス/現金レジ精算・商品引き渡し管理**を一元化したWebアプリケーションです。

サーバー費用ゼロ（完全無料枠）での安定稼働を実現するため、**GitHub Pages（静的フロントエンド）** と **Google Apps Script \+ Google スプレッドシート（バックエンド・データベース）** を分離した構成を採用しています。

---

## **主な機能**

### **1\. 来場者向け事前注文画面 (`index.html`)**

* **アカウント認証 & 固定会員QRコード発行:**  
  * Gmailアドレスを入力するとユーザーID（`USR-1001` 等）が1対1で発行され、専用のQRコードを生成します。  
  * 複数回に分けて注文した場合でも、会員QRコード画面内の「未決済のご注文」で**商品ごとに個数・金額を自動合算**して表示します。  
  * 会員QRコードはユーザー固有の固定値のため、スクリーンショットを保存しておけばレジ前で通信せずに提示できます。  
* **リアルタイム在庫連動 & カート機能:**  
  * 残り在庫数・購入上限数（`limit`）を自動判定し、在庫切れ商品の選択や上限超過を防止します。  
  * 通信待機中は全画面ローディングスピナーを表示し、二重送信を防止します。  
* **スタッフアカウント自動判別:**  
  * スタッフとして登録されたアカウントで認証した場合のみ、画面上部にスタッフ管理画面へのクイックリンクが表示されます。

### **2\. スタッフ向け管理・POSレジ画面 (`staff.html`)**

* **スタッフ認証:**  
  * `staffs` シートに登録されたGmailアドレスとパスコード（PIN）による認証機能を備えています。  
* **レジ決済（POS）タブ:**  
  * 端末の背面カメラを用いた**軽量ライブQRスキャン**（250ms間隔・縮小フレーム解析）およびユーザーIDの手入力検索に対応しています。  
  * 対象ユーザーの未決済注文（`status: 0`）をすべて抽出し、**商品別に個数・小計を合算**して一括会計を行います。  
  * お預かり金額を入力するとお釣りを自動計算し、決済完了時にスプレッドシートへお預かり金額（`received_amount`）を記録します。  
* **商品引き渡し（ピッキング）タブ:**  
  * 決済済みの注文を**ユーザー単位（`USR-xxxx`）で合算**して一覧表示します。  
  * オペレーションミスを防ぐため、ステータスに応じて **「ピッキング開始」→「引き渡し完了」** の順で1ボタンずつ段階的に表示します。  
* **ダッシュボードタブ:**  
  * 総売上金額・有効注文件数・商品ごとの販売数および現在庫数をリアルタイムで集計します。

### **3\. バックエンド自動管理 (`Code.gs` / `Setup.gs`)**

* **排他制御（`LockService`）:** 同時注文・同時決済による在庫不整合やデータ上書きを防止します。  
* **高速キャッシュ（`CacheService`）:** 商品一覧データをキャッシュし、アクセス集中時のスプレッドシート読み取り負荷を軽減します。  
* **期限切れ注文の自動キャンセル:** 注文確定から1時間経過しても未決済の注文を10分間隔のトリガーで自動キャンセルし、在庫を自動で戻します。

## **システム構成・ファイル一覧**

```
├── index.html      # 来場者向け事前注文画面
├── staff.html      # スタッフ向けPOSレジ・引き渡し・売上管理画面
├── staff.css       # スタッフ画面用スタイルシート
├── staff.js        # スタッフ画面用ロジック（QRスキャン・POS・ピッキング・集計）
├── config.js       # GAS APIのURL設定・共通通信ヘルパー・ローディングスピナー制御
└── gas/            # Google Apps Script（スプレッドシートのApps Scriptエディタに配置）
    ├── Code.gs     # APIエンドポイント（doGet / doPost）・在庫計算・DB操作
    └── Setup.gs    # スプレッドシート4シート自動構築・トリガー初期設定スクリプト
```

## **セットアップ手順**

### **Step 1: Google スプレッドシート & GAS の準備**

1. Google ドライブで新規の Google スプレッドシートを作成します。  
2. メニューの **「拡張機能」＞「Apps Script」** を開きます。  
3. エディタ上で Code.gs と Setup.gs を作成し、それぞれのコードを貼り付けて保存します。  
4. エディタ上部の関数選択プルダウンから **setupAllSheets** を選択して **「実行」** をクリックします（初回のみアクセス権限の承認が必要です）。  
   1. 実行すると、products / orders / users / staffs の4シートと10分おきの自動キャンセルトリガーが自動生成されます。  
5. スプレッドシートに戻り、**products シート**に販売商品情報、**staffs シート**にスタッフのGmailアドレスとPINを設定します。

### **Step 2: GAS ウェブアプリのデプロイ**

1. Apps Script エディタ右上の **「デプロイ」＞「新しいデプロイ」** をクリックします。  
2. 種類の選択で **「ウェブアプリ」** を選び、以下のように設定して「デプロイ」します。  
   1. **次のユーザーとして実行:** 自分  
   2. **アクセスできるユーザー:** 全員  
3. 発行された **ウェブアプリのURL**（https\://script.google.com/macros/s/.../exec）をコピーします。

### **Step 3: フロントエンドの設定 & GitHub Pages 公開**

1. config.js を開き、GAS\_API\_URL に Step 2 でコピーしたURLを設定します。  
2. リポジトリにすべてのフロントエンドファイルをプッシュします。  
3. GitHub リポジトリの **Settings ＞ Pages** から公開ブランチを選択し、GitHub Pages を有効化します。

## **データベース仕様（Google スプレッドシート）**

| シート名 | カラム構成（1行目ヘッダ） | 役割 |
| :---- | :---- | :---- |
| **products** | id, name, price, stock, limit, image\_url, status | 商品マスタ（stock は初期在庫数を入力。現在庫は注文データから自動計算） |
| **orders** | id, created\_at, total\_price, status, updated\_at, items, received\_amount | 注文履歴・決済金額・ステータス管理 |
| **users** | user\_id, account, created\_at | 来場者のGmailアドレスとユーザーID（USR-xxxx）の1対1対応表 |
| **staffs** | name, account, pin | スタッフ画面ログイン用の認証マスタ |

### **注文ステータスコード (orders.status)**

* 0: 未決済（注文確定直後・レジ支払い待ち）  
* 1: 決済済み（ピッキング待ち）  
* 2: ピッキング中（引き渡し準備中）  
* 3: 引き渡し完了  
* 4: キャンセル済み（在庫自動返却済み）

## **イベント当日の運用上の注意**

* **同時アクセス制限の回避:** GASの仕様上、ウェブアプリの同時実行数は最大30リクエストです。スタッフ端末の台数は必要なレジ・引き渡し担当分（推奨2〜4台）に絞り、不要なリロード連打は控えてください。  
* **QRコードのスクリーンショット推奨:** 来場者には注文完了後のQRコード画面をスクリーンショット保存してもらうことで、レジ前での通信待機時間をゼロにできます。  
* **商品マスタの編集:** イベント中に products シートを直接編集した場合は、キャッシュが自動クリアされます。即座に端末へ反映したい場合は、画面右上の「在庫更新 / 更新」ボタンを押してください。
